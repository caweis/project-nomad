### Where the picture feature differs from upstream
- **Capability from `/api/show` only**, never from the model list, so 26f40baf's
  fix needed no code here. On the oMLX proxy the answer is always "unknown":
  its placeholder capability list says nothing about the model.
- **Pictures ride as base64 `images`** on the newest user message, which is
  Ollama's field; the oMLX proxy turns them into `image_url` parts. Upstream
  builds OpenAI-style data URLs.
- **The context budget** holds room for the pictures, up to a share of the
  window, and remembers less of an older conversation to do it.
- **Upload checked by size only.** Upstream gives the upload parser a list of
  extensions, and its check is case-sensitive, so `IMG_0001.JPG` was refused
  with a 415. Fixed here (`022d09ed`); upstream's controller has the same list.
  What decides is the decoded image.
- **One file of limits** for the page and the server, and a picture over 40
  megapixels now says what the limit is instead of "could not be decoded".
  Three choices about those limits are left open in caweis#60: they are checked
  after the upload is on disk, a very large picture takes seconds to decode, and
  the answer budget assumes a capped picture cost.
- **Interrupted uploads are swept.** The multipart parser leaves the files it
  had finished when a request dies part-way, and for a chat those are the
  untouched originals. Upload files are named `nomad-upload-<uuid>`, and one
  that nothing has written to for six hours is removed (`13b1e4a4`). Upstream's
  parser configuration sets no file name and has no sweep (checked at
  `54ee30a4`).
- **Guidance says what is known.** `gemma3:1b` is text-only and is the gemma3
  that the smallest model set installs; on MLX the Models page installs the
  smallest build in a family. What a text-only MLX model does with a picture
  (fail, or ignore it) was not run.

### Where the Translated Library differs from upstream
- **No image of our own.** The seeder pins upstream's published `0.1.1`, and
  the CI workflow that publishes it (85da9280) is not ported: it pushes to
  their registry and runs only for their deployment list.
- **Platform.** The image is `linux/amd64` only. The seeder entry names the
  platform and `DockerService` passes it to the pull and to the create on
  install, update and recreate.
- **Open question: AVX.** The `bergamot` wheel is built with
  `-march=core-avx-i` and uses AVX from module start-up. Whether Rosetta runs
  that in a Linux container is not settled (Apple's Mac-app page says AVX and
  AVX2 are translated; a forum thread reported they were not exposed to Linux
  VMs as of April 2025). `install/nomad-translate/FORK_NOTES.md` has a check
  that takes a few seconds. Run it before relying on the app.
- **Display order** 13, to fit this fork's range (upstream 28). Everything
  else in the seeder entry is upstream's.

### Edit on every installed app
- Upstream's `02c33b27` had a backend half and a menu half. The backend, the
  model column, the migration and the stale-`_old` cleanup were already here;
  the menu showed Edit for custom apps only. Now it is in the ⋯ menu of every
  installed app that runs in a container (the native AI Assistant has none).
- **A modified tag** shows an edited shipped app, which the reseed then skips.
  Its colors give 5.5:1 in light mode and 9.0:1 in dark mode.
- **Read-only mounts survive an edit.** MeshCore Web's two `:ro` binds made its
  dialog unsaveable (the container path showed `:ro`, which the validator
  refuses); the options are now kept out of the dialog and put back on save.

### Where the link tiles differ from upstream
- **Placement.** The fork's home shows pinned apps only. Tiles are always
  pinned and sit in their own Your links deck, after the app decks, with no
  pin toggle. Upstream's dashboard has no decks, so it had nothing to decide.
- **Left out of the Supply Depot, the Apps page and the nightly update check.**
  Upstream lists tiles in the Supply Depot, where every action would act on a
  container that does not exist, and checks each one's empty image for updates.
- **Edit and Remove always visible**, not on hover, for touch screens.
- **One URL check** (`util/custom_url.ts`) for the server and the form, where
  upstream keeps a copy on each side. It also reports why it refused a URL, so a
  URL that is only too long is not called invalid.
- **Validators in `validators/link_tile.ts`**, so `validators/system.ts` stays
  loadable by the standalone harness. **Routes gated** with `localNetworkOnly`.
  **409 and 422** reach the user in the server's words.

### Where the knowledge-base switch differs from upstream
- **No grouped table.** Upstream groups files under collapsible collection
  headers with a switch on each. This fork's panel organises by its Show
  filter (13f13896), so the bulk switch acts on the collection shown.
- **Named collections only.** Upstream's Uncategorized switch reaches, on
  the server, every point with no collection: every ZIM and NOMAD's own help
  pages, though its screen lists only uploads under that heading.
- **Rows for files that had none** (pre-RFC #883 data, NOMAD's help pages)
  are recorded as indexed, so the switch shows what search does. The same
  helper stops the fork's collection change recording such files as pending,
  which offered Index and, under Always, embedded them a second time.
- **Race closed:** the row is written before the points, and each embed
  write re-reads it and corrects its own points.
- **Backfill not awaited**, and `hasDocuments` counts only searchable points.
- **Switches named for screen readers**, each with its own id; the header is
  "In answers" so the table fits at 1024px.

### Defects found in the fork's own Unreleased work (all fixed above)
First pass:
- **0.2.765 cap** — every chat answer capped at 1,024 tokens (b87f7ea).
- **f3f1960 (caweis#51)** — changelog said walking away stops the answer; only
  the browser stopped (87a7073, gated by 43952ca).
- **3bf5c9c (caweis#50)** — the delete-time purge used a Qdrant client that was
  never initialised, so it always failed silently (d40a6d9); the sweep's root
  narrowing did not narrow to walked roots (c20cca3).
- **6887c37** — `eval:retrieval` would have scored zero recall on any golden
  set (1889a8b).

Second pass, found by review of the work above (all fixed):
- **Upper-case picture names refused** (`022d09ed`): the upload parser's
  extension check is case-sensitive. Upstream has the same list.
- **A replaced ZIM kept its text** (`8282445c`): `RunDownloadJob` repointed the
  row and deleted the old file without purging, so after an update that
  replaces many files the sweep's mass-removal guard would hold the stale
  sources back for good. The guard's own comment assumed the purge happened.
- **MeshCore Web could not be saved** from the new Edit (`a43524e5`).
- **Guidance that overclaimed** (`fc1e5034`, `a87b86e2`): `gemma3` named as a
  model that can see (the 1b is not); "will fail" for a text-only MLX model
  (not run); "disappear after you send them" (they stay on screen until a
  reload); the Translated Library described as costing "some speed" on a Mac
  when nothing has run there.
- **The composer** (`93a6e048`): a refused file ahead of usable ones skewed the
  count; focus was lost on removing a picture by keyboard; the reason the
  attach button is off was invisible to a screen reader; two texts were under
  4.5:1.
- **A reader who left while pictures were processed** (`206c18af`): the server
  resizes the pictures and asks the model what it can do before the controller
  starts watching for the reader, and a `close` listener attached after the
  socket has closed never fires. Stop, a new message or a change of
  conversation in that time left the full answer being generated for nobody,
  the next question waiting behind it, and the abandoned answer saved.
- **Originals left in the temp folder** (`13b1e4a4`): a request that failed
  inside the parser, because the tab closed or the connection dropped, never
  reached the controller's clean-up, and the files the parser had already
  finished stayed in the admin container's temp folder, camera and location
  details included. The same held for any interrupted upload.

## Decisions for Chris
- **932ced39**: take upstream's `maxStalledCount: 0` for embeddings, or keep
  the fork's deliberate 3 and make point IDs deterministic so a re-run
  overwrites instead of duplicating.
- **Offline translation**: whether to build and publish an arm64
  `nomad-translate` image, given model size and licensing (caweis#54). If the
  check in `FORK_NOTES.md` fails under Rosetta, whether to pull the catalog
  entry until there is one.

  upstream now does, and the help pages no longer spell it out. About has no
  origin line; adding upstream's is a one-line change.
- **Release**: Unreleased carries the 1,024-token fix for a regression 0.2.765
  shipped, and the ports of both passes; worth cutting 0.2.766 after the device
  pass.
- **Tracking** (decided): caweis#56 holds the device pass and what is left. This
  ledger is the record.
- **Link tile placement** (decided here, easy to change): always pinned, in a
  deck of their own, with no pin toggle. Mixing tiles into the app decks, or
  letting them be unpinned, would first need somewhere else to find an
  unpinned tile, since the Supply Depot leaves them out.
- **Knowledge-base layout**: keep the Show filter, or adopt upstream's grouped
  table (collection headers, and NOMAD's help pages rolled into one row, which
  upstream has had since v1.32 and this fork never took).
- **A ZIM's switch across editions**: a newer edition arrives under a new file
  name and starts switched on, upstream too. Carrying the switch over would
  mean matching editions by book name.
