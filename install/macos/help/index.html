What this distribution adds

Upstream Project NOMAD's installer is Linux-only and assumes NVIDIA GPU passthrough. This bundle is a distribution layer on top of snfettig's macOS port and proximasan's admin patches. It adds:

  • Single-file nomad CLI with subcommand-based lifecycle (install / check / up / down / restart / logs / models / benchmark / fix-kiwix / install-field-desk / and more).
  • Native Metal Ollama via Homebrew + LaunchAgent on port 11434. Verified ~8× faster than container Rosetta on Apple Silicon (20.76 tok/s vs 2.56 tok/s on Mac mini M4).
  • Split storage for unplug-resilience — mysql + redis on internal disk; ZIMs / models / maps on a configurable external drive that can be safely unplugged.
  • OrbStack VM auto-tune to ~80% of host RAM (proportional, scales 8 GB Air → 192 GB Studio).
  • Three LaunchAgents running in the background — see below.
  • Portable quick-chat.html dropped on the data drive — plug into any Mac and have LLM chat without a NOMAD install.
Quick orientation Crosstalk admin UI at localhost:8080 · this kiwix server at localhost:8090 · native Ollama API at http://localhost:11434.

The three LaunchAgents

These run automatically. You don't normally interact with them. Each writes only when it does work, so silent logs = healthy state.

AgentWhat it doesLog location
com.projectnomad.ollama Native Ollama daemon. Resolves the data drive at runtime so renamed mounts don't break it. system console
com.projectnomad.benchmark-patcher Every 30s. Backfills cpu_model / gpu_model on admin's benchmark_results rows so the upstream leaderboard sees the real Apple chip instead of "—". ~/Library/Logs/nomad-benchmark-patcher.{out,err}.log
com.projectnomad.kiwix-self-heal Every 60s. Two jobs in one tick: (1) quarantine partial ZIMs that crash kiwix-serve to storage/zim-inprogress/ · (2) auto-reload kiwix when new completed ZIMs appear in /data and the queue is empty. ~/Library/Logs/nomad-kiwix-self-heal.action.log

Why kiwix sometimes shows fewer ZIMs than admin

Two views of two different states — and both are correct in their own frame:

  • Admin's Content Manager = files admin's downloader has written to /data. Tracked in admin's DB regardless of kiwix's state.
  • Kiwix's catalog = files kiwix-serve loaded at its last startup. Kiwix-serve doesn't watch /data for new files — once it's running, its in-memory library is fixed.

If admin shows 88 ZIMs and kiwix shows 61, the com.projectnomad.kiwix-self-heal agent is likely waiting for the download queue to empty before triggering a kiwix restart. The auto-reload's gate logic:

fs_count > catalog_count  AND  active_zim_downloads == 0  →  restart kiwix

Once active downloads hit 0, the next 60s tick restarts kiwix and the catalog catches up. To check the agent's current decision:

~/.config/project-nomad/kiwix-self-heal.sh
tail -10 ~/Library/Logs/nomad-kiwix-self-heal.action.log
Don't force-reload kiwix while downloads are active A manual docker restart nomad_kiwix_server mid-write will crash kiwix on the partial ZIM, the self-heal will quarantine it, and admin's BullMQ writer will lose the file. Wait for the queue to empty, or use nomad fix-kiwix which respects the gate.

nomad install-field-deskInstall SysAdminDoc's NOMAD Field Desk alongside admin on a non-conflicting port. Default :8081, shares native Ollama on :11434.

nomad uninstallClean wipe — containers, LaunchAgents, secrets. Optionally wipes data drive (separate confirm).
nomad helpShort usage. man nomad for the full reference.

Drive-eject is safe mysql + redis stay running because their data is on internal disk. Admin keeps responding. Content services pause until the drive returns. Native Ollama keeps any already-loaded model in RAM via OLLAMA_KEEP_ALIVE=30m. After replug: nomad up.

The Easy Setup wizard's "AI Models" step

Admin's onboarding wizard at /easy-setup offers a hardcoded "recommended models" trio (llama3.1, deepseek-r1, nomic-embed-text). Skip the AI Models step. Your models are already pulled via native Ollama by nomad install; selecting them in the wizard would queue duplicate downloads through admin's BullMQ queue.

The home page's wizard highlight is suppressed by default (we set kv_store.ui.hasVisitedEasySetup = true at install time), so there's no visual nudge. The wizard remains accessible if you actively want it for the Wikipedia / Maps / Content steps.

Why this matters Selecting AI Models in the wizard queues admin BullMQ jobs that try to spawn admin-managed Ollama downloads. They overlap with what we already pulled via native Ollama and either duplicate work or fail outright. This is an upstream UX issue worth filing — the wizard should query Ollama for already-installed models before offering downloads.

Lineage

The Apple Silicon admin patches that make Metal-aware benchmark reporting work are from the community fork series:

  • snfettig/project-nomad-macos-arm64 — original native-Ollama+Metal commit, current macOS focal point
  • proximasan/project-nomad-silicon — APPLE_CHIP_MODEL fallback, isNativeOllama(), multi-arch GHCR images
  • NoamanKhalil/project-nomad-MacOs — foundational Phase 1-3 macOS port work
  • Crosstalk-Solutions/project-nomad — upstream

Sibling product worth knowing about (different architecture, not a fork): SysAdminDoc/project-nomad-desktop — NOMAD Field Desk, a Python+Electron preparedness command center. Coexists with admin via nomad install-field-desk.
