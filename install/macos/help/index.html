Project NOMAD — macOS Distribution Help

You're running the macOS distribution layer of Project NOMAD. This page explains what's installed, how the pieces fit together, and how to recover when something looks off.

Quick orientation: the Crosstalk admin UI lives at http://localhost:8080 · kiwix (Wikipedia, ZIMs) at http://localhost:8090 · native Ollama at http://localhost:11434.

What this distribution adds

Upstream Project NOMAD's installer is Linux-only and assumes NVIDIA GPU passthrough. This bundle is a distribution layer on top of snfettig's macOS port and proximasan's admin patches. It adds:

  • Single-file nomad CLI with subcommand-based lifecycle (install / check / up / down / restart / logs / models / benchmark / fix-kiwix / install-field-desk / etc).
  • Native Metal Ollama via Homebrew + LaunchAgent on port 11434, talking to admin via host.docker.internal. Verified ~8× faster than container Rosetta on Apple Silicon.
  • Split storage for unplug-resilience — mysql + redis on internal disk; ZIMs / models / maps on a configurable external drive that can be safely unplugged.
  • OrbStack VM auto-tune to ~80% of host RAM (proportional, scales 8 GB Air → 192 GB Studio).
  • Three LaunchAgents running in the background — see below.
  • Portable quick-chat.html dropped on the data drive — plug into any Mac and have LLM chat without a NOMAD install.

The three LaunchAgents

These run automatically. You don't normally interact with them. Each writes only when it does work, so silent logs = healthy state.

AgentWhat it doesLog location
com.projectnomad.ollamaNative Ollama daemon. Resolves the data drive at runtime so renamed mounts don't break it.system console
com.projectnomad.benchmark-patcherEvery 30s. Backfills cpu_model / gpu_model on admin's benchmark_results rows so the upstream leaderboard sees the real Apple chip instead of "-".~/Library/Logs/nomad-benchmark-patcher.{out,err}.log
com.projectnomad.kiwix-self-healEvery 60s. Two jobs: (1) quarantine partial ZIMs that crash kiwix-serve to storage/zim-inprogress/ · (2) auto-reload kiwix when new completed ZIMs appear in /data and the queue is empty.~/Library/Logs/nomad-kiwix-self-heal.action.log

Why kiwix sometimes shows fewer ZIMs than admin

Two views of two different states:

  • admin's Content Manager = files admin's downloader has written to /data. Tracked in admin's DB regardless of kiwix's state.
  • kiwix's catalog = files kiwix-serve loaded at its last startup. kiwix-serve doesn't watch /data for new files — once it's running, its in-memory library is fixed.

If admin shows 88 ZIMs and kiwix shows 61, the com.projectnomad.kiwix-self-heal agent is likely waiting for the download queue to empty before triggering a kiwix restart. The auto-reload's gate logic:

fs_count > catalog_count  AND  active_zim_downloads == 0  →  restart kiwix

Once active downloads hit 0, the next 60s tick restarts kiwix and the catalog catches up. To check the agent's current decision:

~/.config/project-nomad/kiwix-self-heal.sh
tail -10 ~/Library/Logs/nomad-kiwix-self-heal.action.log

Common subcommands

CommandPurpose
nomad checkFull diagnostic of system + stack. Read-only. Writes a timestamped log file to the bundle folder.
nomad up / nomad downStart / stop the compose stack. Native Ollama LaunchAgent is unaffected.
nomad restart [SERVICE]Restart any compose service OR any admin-spawned container (kiwix, kolibri, cyberchef, etc). Default: admin.
nomad logs [SERVICE]Tail logs (default: admin).
nomad models listList installed Ollama models with per-Mac fits-this-Mac verdict.
nomad models pull TIERPull a tier preset (tiny/small/medium/large/xl/dreamy). Auto-detected from RAM by default.
nomad benchmarkNative Metal vs container Rosetta tokens/s on llama3.1:8b. Captures the Apple chip via the auto-patcher LaunchAgent.
nomad fix-kiwixManual trigger of the kiwix self-heal pass. Verbose output. Use when you want immediate recovery instead of waiting for the next 60s tick.
nomad install-field-deskInstall SysAdminDoc's NOMAD Field Desk alongside admin on a non-conflicting port. Default :8081, shares native Ollama on :11434.
nomad orbstack-tune [GB]Tune OrbStack VM RAM. No arg = 80% of host. Restarts the VM (~10s).
nomad reset-ollamaRecover from stuck LaunchAgent state ("bootstrap failed: 5: Input/output error").
nomad reinstallFull uninstall + install in one shot. One confirmation up front, fully unattended after.
nomad uninstallClean wipe — containers, LaunchAgents, secrets. Optionally wipes data drive (separate confirm).
nomad helpShort usage. man nomad for the full reference.

  ~/.config/project-nomad/state/mysql/      mysql data dir
  ~/.config/project-nomad/state/redis/      redis data
  ~/.config/project-nomad/.env              secrets (chmod 600, off-iCloud)
  ~/.config/project-nomad/kiwix-self-heal.sh
  ~/.config/project-nomad/benchmark-patcher.sh
  ~/.config/project-nomad/ollama-launcher.sh
  ~/Library/LaunchAgents/com.projectnomad.*.plist

CONFIGURABLE — typically external, cold content
  ${NOMAD_DATA_ROOT}/storage/zim/           kiwix's ZIM library
  ${NOMAD_DATA_ROOT}/storage/zim-inprogress/  partial ZIMs quarantined by self-heal
  ${NOMAD_DATA_ROOT}/storage/maps/          ProtoMaps PMTiles
  ${NOMAD_DATA_ROOT}/storage/kolibri/       Kolibri channels
  ${NOMAD_DATA_ROOT}/ollama-models/         model weights
  ${NOMAD_DATA_ROOT}/quick-chat.html        portable browser chat UI
  ${NOMAD_DATA_ROOT}/quick-chat.sh          companion bootstrap script
Drive-eject is safe. mysql + redis stay running because their data is on internal disk. Admin keeps responding. Content services pause until the drive returns. Native Ollama keeps any already-loaded model in RAM via OLLAMA_KEEP_ALIVE=30m. After replug: nomad up.

The Easy Setup wizard's "AI Models" step

Admin's onboarding wizard at /easy-setup offers a hardcoded "recommended models" trio (llama3.1, deepseek-r1, nomic-embed-text). Skip the AI Models step. Your models are already pulled via native Ollama by nomad install; selecting them in the wizard would queue duplicate downloads through admin's BullMQ queue.

The home page's wizard highlight is suppressed by default (we set kv_store.ui.hasVisitedEasySetup = true at install time), so there's no visual nudge to run it. The wizard remains accessible via the Easy Setup card if you actively want it.

Lineage

The Apple Silicon admin patches that make Metal-aware benchmark reporting work are from the community fork series:

  • snfettig/project-nomad-macos-arm64 — original native-Ollama+Metal commit, current macOS focal point
  • proximasan/project-nomad-silicon — APPLE_CHIP_MODEL fallback, isNativeOllama(), multi-arch GHCR images. compose.yaml here references proximasan's images by default.
  • NoamanKhalil/project-nomad-MacOs — foundational Phase 1-3 macOS port work
  • Crosstalk-Solutions/project-nomad — upstream

Sibling project worth knowing about (different product, not a fork): SysAdminDoc/project-nomad-desktop — NOMAD Field Desk, Python+Electron preparedness command center. Coexists with admin via nomad install-field-desk.
